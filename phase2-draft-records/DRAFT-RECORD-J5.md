NOT ADOPTED, under the fail-closed default.

## Terms

1. **Candidate.** Candidate tool or model: TBD. What it replaces: TBD.
   What it must prove before adoption: TBD. No candidate is named in
   this record, and no candidate has been evaluated under it.
2. **Evaluation checklist.** Every evaluation must answer, in writing,
   with evidence attached: (a) what the tool replaces; (b) what it must
   prove, and the pass/fail rule stated before the evaluation runs;
   (c) cost, including any per-use, per-seat, or infrastructure cost —
   amount: TBD; (d) failure mode, and what happens when it fails;
   (e) exit route, and how work leaves the tool if it is dropped.
3. **Evidence.** Every evaluation is logged as a decision record with
   its evidence attached. A claim without attached evidence is
   UNRESOLVED, NOT CLEARED. Evidence collected on synthetic fixtures
   only is labelled synthetic and never substitutes for evidence on
   real pairs, of which there are still zero in the record.
4. **Cost ceiling.** Predeclared cost ceiling for adoption: TBD. No
   number is set in this draft. An evaluation without a predeclared
   ceiling does not proceed.
5. **Decision.** The decision record states ADOPT, REJECT, or DEFER,
   with the evidence cited. Silence, delay, or a missing signature
   never counts as adoption. Approver: TBD. Review cadence: TBD.
6. **Prototype link.** Evaluation runs, if any, use the Phase 1
   prototype harness only, on synthetic inputs, under the governance in
   CREATOR-SKILLS-IMPLEMENTATION.md Part C. No live account, no API key,
   and no sending channel is authorised by this record.
